# PROJECT SPECIFICATION: Dynamic CV & Cover Letter Generator Bot

## 1. Executive Summary & Business Context
**Problem Statement:** 
Користувач має нагальну потребу змінити поточне місце роботи (готельний бізнес) і розглядає вакансії в різних сферах (IT, гостинність, суміжні напрямки). Наявність великого, але різнопланового бекграунду створює проблему: підготовка релевантного резюме та супровідного листа під кожну нову вакансію займає занадто багато часу і створює "тертя" (friction), що гальмує процес пошуку роботи.

**Proposed Solution:** 
Створити автоматизовану систему (Telegram-бота), яка працюватиме за принципом "Single Source of Truth" (Єдине джерело істини). Користувач створює один великий майстер-файл зі всім своїм досвідом, а бот, використовуючи AI, "відсікає" зайве і формує ідеально підігнане під конкретну вакансію ATS-friendly резюме та Cover Letter у форматі PDF.

**Core Philosophy:** 
Швидкість, прагматичність, Vibe-Coding. Проєкт має бути створений швидко для вирішення нагальної проблеми, але з архітектурою, яка дозволить масштабувати його в майбутньому або перенести на інший стек технологій.

## 2. System Architecture & Core Concept

### 2.1. The "Single Source of Truth" (SSOT) Pattern
Замість підтримки десятків файлів, створюється єдиний `master_profile.md`.
- **Вміст:** Увесь можливий досвід (готель, автосалон, IT-пет-проєкти, відеомонтаж, мови, софт-скіли).
- **Структура:** Чіткі заголовки (`## Досвід`, `## Навички`), теги або ключові слова, щоб AI було легше парсити дані.
- *Простір для розвитку:* У майбутньому цей файл можна замінити на Notion Database або повноцінну SQL/NoSQL базу даних, де кожен скіл буде окремим записом з ваговими коефіцієнтами.

### 2.2. Pipeline (Потік даних)
1. **Input (Вхідні дані):** Користувач надсилає боту опис вакансії (текстом або URL).
2. **Context Merge (Об'єднання контексту):** Бот бере текст вакансії та `master_profile.md`.
3. **AI Processing (Робота алгоритму):** 
   - *Фільтрація:* AI вибирає лише релевантний досвід.
   - *Адаптація:* AI переписує формулювання досягнень так, щоб вони відповідали ключовим словам вакансії (ATS оптимізація).
   - *Генерація:* AI створює тимчасовий `tailored_cv.md` та `cover_letter.md`.
4. **Rendering (Генерація PDF):** 
   - Markdown конвертується в чистий HTML.
   - Застосовуються ATS-friendly CSS стилі.
   - HTML рендериться у PDF (текстовий шар зберігається).
5. **Output (Результат):** Бот надсилає готові PDF файли користувачу в Telegram.

## 3. Technology Stack Options

### Option A: The JS/TS Web-Tech Stack (Рекомендовано для генерації PDF)
- **Language:** JavaScript / TypeScript (Node.js)
- **Bot Framework:** `grammY` або `Telegraf` (швидкі та сучасні).
- **AI Integration:** `@google/generative-ai` (Gemini SDK).
- **Rendering Engine:** 
  - `marked` (для парсингу MD -> HTML).
  - `puppeteer-core` (для генерації ідеального PDF з HTML).
- **Pros:** Найкраща екосистема для роботи з HTML/CSS та друку в PDF; легко підтримувати сучасний дизайн резюме.

### Option B: The Python Legacy Stack (Fallback)
- **Language:** Python 3.x
- **Bot Framework:** `aiogram` або `telebot`.
- **AI Integration:** `google-genai` або `requests` (з урахуванням попередніх багів SSL на Mac).
- **Rendering Engine:** `weasyprint` (конвертація HTML/CSS в PDF).
- **Pros:** Знайомий стек з попереднього проєкту, легко перенести існуючу Clean Architecture.
- **Cons:** Верстка красивих PDF у Python часто складніша і менш гнучка, ніж через браузерний рушій (Puppeteer).

## 4. ATS (Applicant Tracking System) Considerations
*ATS не мають очей, вони читають код документа.*

**Жорсткі інженерні правила для рендерингу резюме:**
1. **Semantic HTML:** Використовувати виключно правильні теги (`<h1>`, `<ul>`, `<p>`).
2. **DOM Order:** Візуальний порядок має 100% відповідати порядку в коді. Жодних CSS-трюків (`flex-direction: row-reverse`, `position: absolute`), які міняють блоки місцями.
3. **Clean Text Layer:** Puppeteer/WeasyPrint має генерувати PDF зі справжніми текстами (не зображеннями). Не використовувати графічні прогрес-бари для скілів — тільки текст.
4. **Standard Fonts & Bullets:** Використовувати стандартні шрифти (Arial, Helvetica, Roboto) та стандартні маркери списків.

## 5. Known Limitations & Room for Future Development (Простір для розвитку)

У цій секції описані "сліпі зони", де алгоритми AI або поточна логіка можуть давати збій, і як ми плануємо це вирішувати.

### 5.1. Проблема "Занадто креативного AI" (Hallucinations)
- **Ризик:** Gemini може придумати досвід, якого не було в `master_profile.md`, просто щоб догодити вакансії, або видалити дати, створивши "дірки" в стажі.
- **Можливе рішення:** Впровадження строгого "System Prompt", який забороняє змінювати дати та вигадувати навички. 
- *Простір для розвитку:* Додати крок "Human-in-the-loop" (Бот спочатку надсилає згенерований текст у Telegram, користувач підтверджує його кнопкою "Approve", і лише після цього генерується PDF).

### 5.2. Проблема мультимовності
- **Ризик:** Вакансія може бути німецькою, угорською або англійською. Резюме теж має адаптуватись.
- **Можливе рішення:** AI повинен першим кроком визначати мову вакансії і перекладати відфільтровані дані з `master_profile.md` на відповідну мову.
- *Простір для розвитку:* Зробити `master_profile.md` двомовним від самого початку, щоб AI не губив контекст при перекладі технічних термінів.

### 5.3. Розриви в досвіді (Employment Gaps)
- **Ризик:** Якщо для ІТ-вакансії ми видаляємо досвід роботи в готелі за останні 2 роки, резюме виглядатиме так, ніби людина не працювала.
- **Можливе рішення:** AI повинен не видаляти нерелевантний досвід повністю, а "стискати" його до одного рядка без розпису обов'язків, щоб зберегти хронологію (наприклад: *2024 - Present: Hospitality Roles (Non-IT)*).

### 5.4. Недосконалість парсингу зовнішніх джерел
- **Ризик:** Алгоритми Jina AI або звичайні скрапери можуть витягувати текст вакансії з "брудом" (реклама, навігація сайту), що зіб'є AI з пантелику.
- **Можливе рішення:** Попередня чистка тексту за допомогою регулярних виразів або окремого швидкого AI-запиту на виділення суто списку вимог.
- *Простір для розвитку:* Інтеграція спеціалізованих API для різних job-бордів (наприклад, LinkedIn API), якщо вони колись стануть доступнішими.

### 5.5. Масштабування на інших користувачів (Multi-user)
- *Простір для розвитку:* Зараз це інструмент для одного (через жорстко заданий Markdown). У майбутньому треба буде додати базу даних (PostgreSQL), де кожен юзер матиме свій збережений `master_profile`.
